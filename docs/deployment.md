# 수동 배포

원본 저장소에서 정본 변경을 커밋한 뒤 실행한다. Python 표준 라이브러리와 Git만 필요하다.

```powershell
python -B tools/sync.py C:\path\consumer --dry-run
python -B tools/sync.py C:\path\consumer
```

소비 프로젝트의 `origin`이 알리는 기본 브랜치 HEAD를 기준으로 계획한다.
그 커밋이 로컬에 없으면 소비 프로젝트에서 `git fetch origin` 후 다시 실행한다.
현재 체크아웃한 브랜치의 프로젝트 입력 대신 최신 기본 브랜치의
`.claude/settings.project.json`을 사용하므로, 이 입력을 먼저 기본 브랜치에 준비한다.
원본 저장소와 소비 프로젝트는 모두 미커밋·미추적 변경이 없어야 한다.
현재 작업 트리가 다른 브랜치여도 배포 브랜치의 부모는 최신 기본 브랜치다.
현재 브랜치의 배포 경로나 관련 `.gitattributes`가 기본 브랜치와 다르면 실제
체크아웃 바이트를 확정할 수 없어 보호한다. 최신 기본 브랜치를 체크아웃해 다시
계획하거나, 계획을 검토한 뒤 `--force`로 정본 바이트를 명시적으로 적용한다.

계획은 `common/` 아래 Git에 커밋된 파일 전부를 같은 상대 경로로 배포한다.
`ADD`, `UPDATE`, `DELETE`는 커밋에 들어갈 변경이며, `ADOPT`는 기존 동일 바이트
파일의 편입, `BLOCK`은 충돌·표류 경로다. 설정 생성과 배포 기록도 계획에 포함한다.
`--dry-run`은 파일·인덱스·브랜치를 변경하지 않는다. 거부할 계획은 종료 코드 1을 낸다.

첫 배포의 기존 파일이 정본과 다르면 멈춘다. 무시된 파일도 충돌 검사 대상이다.
차이를 검토한 뒤 `--force --dry-run`으로 확인하고 `--force`로 적용한다.
이 옵션은 파일 충돌·표류 보호만 해제하며 작업 트리 청결, Git 잠금,
생성 설정 충돌, 경로 구조, 브랜치 생성 조건을 우회하지 않는다.
삭제는 마지막 배포 기록에 있는 경로에만 적용한다. 프로젝트 소유 파일은 유지한다.
이전 배포본의 수정·삭제는 갱신할 경로와 정본에서 삭제된 경로 모두에서 검사하며,
막힌 모든 경로를 `BLOCK`으로 표시한다. 생성 설정은 마지막 기록의 해시 대신
배포된 생성기와 현재 입력으로 재생성한 바이트와 비교한다. 프로젝트 입력을 바꾼
뒤에는 소비 프로젝트에서 `python -B .claude/compose-settings.py`로 재생성하고
함께 커밋한다. 재생성을 빠뜨리거나 생성 설정을 직접 고치면 보호 대상이 된다.

적용하면 `workflow-sync/<정본 SHA 앞 12자리>` 브랜치를 만들고 배포본·생성 설정·
`.workflow-deployment.json`을 단일 커밋으로 남긴다. 기록에는 `source_commit`의 전체
정본 커밋 SHA와 `files`의 배포 경로별 SHA-256을 저장한다. 생성된
`.claude/settings.json`도 기록하고 기록 파일 자체는 해시에 포함하지 않는다.
파일 헤더와 줄바꿈은 변경하지 않는다. 기존 `.claude/compose-settings.py`와 같은
정본 생성기로 설정을 만들며, 프로젝트 입력을 자동으로 만들거나 수정하지 않는다.

커밋 전에 배포 바이트와 설정 재생성을 검사하고, Git 인덱스에서도 바이트가
유지되는지 확인한다. 소비 프로젝트의 기존 Git hook을 정상 실행하며 검사 우회를
설정하지 않는다. hook 실패 등 적용 단계 오류가 발생하면 생성된 브랜치와 작업
상태를 남기므로 오류를 해결하고 검토한다. 커밋 후에도 결과를 검사하며 hook이
배포 내용을 바꿨으면 새 배포 커밋만 브랜치에서 철회하고 인덱스·작업 파일은 보존한다.
검증에는 삭제 대상 파일의 부재도 포함한다. hook이 삭제 파일을 다시 만들면
Git 무시 규칙에 해당하더라도 실패하며, `--force`로 이 검증을 우회할 수 없다.
작업 파일을 자동 복원하거나 강제로 정리하지 않는다.
같은 정본과 프로젝트 입력의 완료된 배포는 재실행해도 추가 커밋이 생기지 않는다.

원격 push와 PR 생성은 사람이 한다. 소비 프로젝트 pre-commit의 독립 표류 검사
연결은 이슈 #23의 범위이며, 이 명령의 배포 후 검증과 별개다.

검증은 `python -B -m unittest discover -s tests -p test_sync.py`로 실행한다.
임시 원본·소비 저장소와 로컬 bare 원격을 사용하며 실제 소비 프로젝트를 변경하지 않는다.
