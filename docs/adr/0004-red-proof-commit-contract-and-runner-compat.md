# red_proof는 `--commit`으로 판정하고 두 가지 러너를 모두 받는다

동작 변경의 red 증명은 대상 커밋의 새·변경 단정 집합이 부모에서 실패한 단정 집합과 정확히 같을 때만 통과한다. 부모는 `git archive`로 푼 격리 사본에 대상의 호스트 테스트를 합쳐 만들고, 작업 트리·stash·worktree를 쓰지 않는다. 대상은 `--commit <rev>`(부모는 `<rev>^`)이나 현재 작업 트리 변경(부모는 `HEAD`)으로 고른다. 이전 `--parent`는 "현재"가 언제나 작업 트리라는 다른 의미였으므로 호환 별칭을 두지 않는다. 작업 트리가 `HEAD`일 때만 `--parent HEAD~1`이 `--commit HEAD`와 같다.

정본 `red_proof.py`는 `TEST_CASES` 러너(`run_test`·`assertion_calls`, 실패 줄 `FAIL: <설명>`)와 `VARIANTS` 러너(`CC`·`CFLAGS`·`main`, 실패 줄 `FAIL <파일>:<줄>  <메시지>`)를 모두 받는다. 전자는 단정을 (실행 파일, 설명)으로 식별하고, 후자는 실패 줄 번호를 대상 소스의 `EXPECT*` 호출 범위로 되짚어 (테스트 TU, 호출 식)으로 식별한다. 검사의 질이 우선이므로 판정 방식은 낮추지 않고 러너 쪽 어댑터만 늘렸다. 소비 프로젝트의 러너를 판정에 맞게 바꾸는 방향(T_N2 방식 이식)이나 소비 프로젝트가 옛 도구를 소유하는 방향은 택하지 않았다.

한계는 도구가 숨기지 않고 드러낸다. 부모에서 빌드가 실패하면 컴파일 실패 red로 인정하지 않고 거부한다. 공용 헬퍼·헤더 안의 단정은 `gcc -MM`으로 포함하는 TU에 귀속하며, 사용처가 `EXPECT*` 이름이 아닌 래퍼 매크로이면 판정 대상 밖이라 사람이 판정한다. `--preprocess`(전처리 동일성)는 `TEST_CASES` 러너만 지원한다. 도구 테스트는 소비 프로젝트 소유라 재배포가 갱신하지 않으므로, 소비 프로젝트는 재배포 때 자기 도구 테스트와 `--parent`를 쓰는 문서를 함께 고친다.
