# 공통 진입점과 프로젝트 확장 지점의 소유권을 분리한다

도구가 정해진 파일 하나를 읽는 진입점에는 공통 자산과 프로젝트 고유 내용이 모인다. 소비 프로젝트가 진입점을 직접 편집하면 공통 갱신과 프로젝트 변경의 경계가 흐려지므로, 진입점은 sync가 관리하고 프로젝트 고유 내용은 별도 확장 지점 파일로 소유한다.

진입점이 실행 중 확장 파일을 읽는 방식을 기본으로 삼는다. git hook은 디스패처와 프로젝트 `.d/`로, 머신 검사는 공통 스크립트와 프로젝트 모듈로 나눈다. 도구가 이 분리를 지원하지 않는 Claude 설정은 공통 조각과 프로젝트 입력을 같은 스크립트로 병합해 생성한다.

이 선택은 프로젝트별 자유로운 진입점 편집 대신 확장 계약을 유지하는 비용을 받는다. 그 대가로 공통 배포본의 동일성을 검사할 수 있고 프로젝트 고유 동작을 보존한 채 갱신할 수 있다. 생성 파일도 입력으로 돌아가 수정해야 하며, 생성기는 소비 프로젝트만으로 실행할 수 있어야 한다. 세부 계약은 [설계서](../workflow-source-spec.md)의 진입점 절을 따른다.
