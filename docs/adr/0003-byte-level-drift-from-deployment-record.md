# 배포 기록에 근거해 바이트 단위로 표류를 판정한다

소비 프로젝트는 원본 저장소 없이 수정된 배포본을 탐지해야 하며, 정본이 앞서간 상태와 소비 프로젝트에서 배포본을 고친 상태를 구분해야 한다. 따라서 전체 정본 커밋 SHA와 경로별 SHA-256을 배포 기록에 남기고, 일반 배포본은 마지막 배포 상태를 기준으로 검사한다. 최신 정본보다 오래되었어도 마지막 배포본을 유지하면 업데이트 대상이다.

줄바꿈을 정규화한 비교는 바이트 동일성 계약의 차이를 숨기므로 사용하지 않는다. LF/CRLF 차이도 표류로 판정하고, 반복되는 체크아웃 차이는 `.gitattributes`를 고쳐 해소한다. 파일 헤더를 바꾸는 대신 별도 배포 기록을 커밋해 버전과 비교 기준을 함께 보존한다.

생성된 `settings.json`은 프로젝트 입력이 바뀔 수 있으므로 현재 입력을 같은 생성기로 병합한 결과와 비교한다. 이 판정은 정상적인 확장 지점 변경을 수용하면서 생성 파일 직접 편집을 드러낸다. 배포 기록을 수동으로 고쳐 차이를 숨기지 않으며, 중간 커밋의 일회성 우회 이후에도 PR 병합 전에는 정상 검사를 통과해야 한다. 운영 계약은 [설계서](../workflow-source-spec.md)의 배포 기록·표류 판정 절을 따른다.
