# 코드 리뷰 smell baseline

Standards 리뷰어가 문서화된 표준(`AGENTS.md`·`test/AGENTS.md`·`CODING_STANDARDS.md`) 위에 얹어 보는 고정 목록이다(Fowler, _Refactoring_ 3장).
출처는 스킬 `code-review` 3단계이고, 코덱스 워커는 스킬을 읽지 못하므로 프로젝트 코드 리뷰 안내에서 이 파일을 spec 에 통째로 붙인다.

- **저장소 표준이 이긴다.** 문서화된 표준이 허용하는 것은 smell 로 지적하지 않는다.
- **전부 판단이다.** "Feature Envy 가능성" 처럼 이름을 붙인 휴리스틱이고 하드 위반이 아니다. 도구(호스트 게이트·`lint_gate.py`)가 이미 막는 것은 건너뛴다.

smell 은 _무엇인가_ → _어떻게 고치나_ 순서다. diff 에 대어 본다.

- **Mysterious Name**: 이름이 하는 일·담은 값을 드러내지 못하는 함수·변수·타입. → 이름을 바꾼다. 정직한 이름이 안 나오면 설계가 흐린 것이다.
- **Duplicated Code**: 같은 로직 모양이 변경 안의 둘 이상의 hunk·파일에 있다. → 공통 모양을 뽑아 양쪽에서 부른다.
- **Feature Envy**: 자기 데이터보다 다른 객체의 데이터를 더 만지는 함수. → 그 데이터 쪽으로 옮긴다.
- **Data Clumps**: 같은 필드·인자 몇 개가 늘 같이 다닌다(타입이 되고 싶은 것). → 하나로 묶어 넘긴다.
- **Primitive Obsession**: 도메인 개념을 원시형·문자열이 대신한다. → 그 개념에 작은 타입을 준다.
- **Repeated Switches**: 같은 타입에 대한 같은 `switch`·`if` 연쇄가 변경 곳곳에 반복된다. → 다형성이나 두 곳이 같이 쓰는 표 하나로 바꾼다.
- **Shotgun Surgery**: 논리적 변경 하나가 diff 의 여러 파일에 흩어진 수정을 강요한다. → 같이 바뀌는 것을 한 모듈로 모은다.
- **Divergent Change**: 한 파일·모듈이 서로 무관한 이유 여럿으로 고쳐진다. → 이유마다 모듈을 나눈다.
- **Speculative Generality**: spec 에 없는 필요를 위한 추상화·인자·훅. → 지우고 진짜 필요가 생길 때까지 인라인한다.
- **Message Chains**: 호출자가 의존하면 안 되는 긴 `a.b().c().d()` 탐색. → 첫 객체의 메서드 하나 뒤로 숨긴다.
- **Middle Man**: 대부분 위임만 하는 클래스·함수. → 없애고 실제 대상을 직접 부른다.
- **Refused Bequest**: 물려받은 것 대부분을 무시하거나 덮어쓰는 하위 타입. → 상속을 버리고 합성을 쓴다.
